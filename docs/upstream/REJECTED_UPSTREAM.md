# Rejected or deferred upstream changes

No individual upstream commit has been rejected after the baseline. The fetched
upstream tip equals the baseline, so there was no new integration candidate.

Wholesale upstream merges are intentionally rejected as an integration strategy.
Upstream branding and future visual redesigns must not overwrite Daisy ownership.
DRM bypass, fake lossless labels, browser-engine replacement and forced telemetry
are outside the product constraints. These are policy decisions, not invented
commit-level rejections.

For future entries record: repository/full SHA, classification, exact reason,
rejected versus deferred status, reconsideration condition, overlapping Daisy
behavior, reviewer/date, and whether security fixes need an alternative port.
